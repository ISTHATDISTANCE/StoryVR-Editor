# Environment Enhancement Lab

This is a standalone experiment for the proposed StoryVR **Environment Enhancement** checkpoint. It does not import or modify the current StoryVR authoring pipeline.

The entire workflow stays in one workspace:

1. Edit an environment search phrase.
2. Search Poly Haven, ambientCG, and Sketchfab through their public APIs.
3. Inspect normalized candidates, licensing, provenance, and available performance metadata.
4. Open the original asset page and download the chosen file yourself.
5. Return to the same screen and upload the downloaded GLB, glTF package, HDR, or EXR.
6. Preview and tune its scale, yaw, height, exposure, and fog.
7. Lock an experimental manifest.

The lab does not request provider credentials or download provider assets on the author's behalf. No scenery is generated by Codex or by keyword-driven geometry.

## Run it

From the standalone StoryVR repository directory:

```bash
node tools/environment-enhancement-lab/server.mjs
```

Open `http://127.0.0.1:5196/`. Standalone uploads are kept in the ignored `tools/environment-enhancement-lab/.lab-data/` directory.

To experiment against a real story while keeping every uploaded asset story-local:

```bash
node tools/environment-enhancement-lab/server.mjs --story-folder <story-slug>
```

Story mode writes only these experimental paths:

- `<story-slug>/webxr-adaptation/public/environment-lab/`
- `<story-slug>/analysis/storyvr/environment-enhancement-lab.json`

It does not update StoryVR decisions, proposals, `story-graph.json`, compiled runtime JSON, or the reader.

## Provider behavior

- **[Poly Haven](https://polyhaven.com/our-api)**: searchable CC0 models and HDRIs. Results link to the original Poly Haven asset page.
- **[ambientCG](https://docs.ambientcg.com/api/)**: searchable CC0 HDRIs, terrains, and 3D assets. Results link to the original ambientCG asset page.
- **[Sketchfab](https://sketchfab.com/developers/download-api)**: public search for downloadable models. Results link to the original Sketchfab model page; the lab does not ask for an API or OAuth token.

The author handles download and license acceptance on the provider's page, then uploads the local artifact. When a search result is selected, its creator, source page, license, and attribution follow the upload into the experiment manifest. The Three.js preview never hotlinks the selected runtime asset.

## Current experiment boundaries

- Upload a `.glb` directly. For glTF with `.bin` files or textures, upload one `.zip` containing the complete package. Embedded `.gltf`, `.hdr`, and `.exr` files are also accepted.
- Uploads are limited to 120 MiB and checked before they enter local story storage. ZIP traversal paths, symbolic links, malformed GLB/glTF, and invalid HDR/EXR headers are rejected.
- The lab does not convert FBX/OBJ scenes, simplify meshes, or recompress textures.
- The author remains responsible for choosing the correct provider download and following its license. Linking a catalog result preserves its available provenance in the manifest.
- Candidate triangle and byte counts are warnings, not a final headset performance certification.
- A selected environment is one persistent story-level layer. It is not linked to individual beats and does not participate in Source Graph, Asset Topology, source motion, or interaction inference.
- Locking writes an experiment manifest only. Integration with the compiled reader is intentionally outside this folder.
